# 故障说明

## BAD_SLIDE 或文本锚点为零

原工具出现过“原始事件很多、文本锚点为零”。这里改为先取文本快照，再读原始事件；提权前要求至少三个不同符号与原始数据匹配、目标关系正确、属于同一次启动。上游最低票数检查仍保留。

检查能减少使用错误采样的机会，不能保证利用稳定。失败后停止并保留本地日志，不要手工填入网上地址、复制别人采样或删掉校验。

## 旧采样能否复用

重启后不能复用。启动期间的内核运行布局可能变化，脚本会核对启动标识。历史日志不是以后能直接加载的物料。

## 中断、卡住和残留进程

上游成功后会保留一个睡眠状态的加载进程，不要看到进程存在就自行强杀。脚本成功时只关闭电脑端等待连接。

如果没成功就断开 USB、关闭窗口或超时，设备端进程可能仍在。停止尝试，保留日志，正常重启后再核对版本、SELinux 和 Root 状态。电脑报错不等于设备自动恢复。

不能正常开机时应先处理设备恢复问题，不继续运行脚本。本仓库不提供适用于所有故障的救砖方案。

## 管理器显示与命令不一致

安装管理器 APK 不等于取得 Root。判断至少需要 uid=0、模块 Live、SELinux Enforcing 和 BL 锁定。此次管理器与配套 ksud 为固定组合，脚本会核对已安装 APK 哈希。

混用其他 Root 管理器、升级管理器或安装修改启动镜像的模块都不在这次测试范围内。

## 提交问题

提供型号、完整内核、增量版本、失败步骤和打码报错即可。不要公开序列号、启动标识、账户、内核运行时地址、整个日志目录或上游工具包。
